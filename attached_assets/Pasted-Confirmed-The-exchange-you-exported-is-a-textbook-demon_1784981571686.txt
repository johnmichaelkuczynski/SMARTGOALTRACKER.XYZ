Why This Happens (Even in a “Smart Goal Tracker”)
Most current LLM apps (including many that claim memory) still rely on:

Long context windows that eventually get truncated or summarized poorly
Simple conversation history that is not structured into a durable case model
No separate “ground truth” store that the model is forced to consult and update
No strong verification loop that checks new statements against previously established facts

Your NEUROTEXT and Text Surgeon architectures already contain the right building blocks for solving this (skeleton extraction, delta reports, GCS / cross-chunk coherence, persistent job state, cognitive profiles, etc.). The Smart Goal Tracker appears not to be using those techniques rigorously.

What a Real “Informed LLM” for This Use Case Needs
For a legal / goal-tracking system that must not forget or contradict itself:

Structured Case State (not just chat history)
Explicit objects: Parties, Documents, Orders, Timeline Events, Claims, Goals, Success Metrics
Stored in the database, not only in the prompt

Mandatory Retrieval + Consistency Check
Before every response, the system must retrieve the current case state and check new statements against it
Flag and correct contradictions before they reach the user

Delta / Update Protocol
Every new piece of information is treated as a delta that is validated and then written into the structured state

Goal & Success Tracking
Explicit goals (e.g., “Get TRO filed Monday 9 AM”, “Preserve chain of custody on forged document”, “Service completed before unfreeze reaches UBS”)
Success/failure logged against those goals

Human-readable Case Brief that is always available
A living, versioned summary the model is required to keep accurate
